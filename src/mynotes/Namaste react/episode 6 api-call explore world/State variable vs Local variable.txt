1️⃣ Local Variable (Normal JavaScript variable)

Example:

const Header = () => {
    let btnName = "Login";

    return (
        <button onClick={() => {
            btnName = "Logout";
        }}>
        {btnName}
        </button>
    )
}
What happens here?

Component renders.

btnName = "Login"

UI shows Login button.

When user clicks button:

btnName = "Logout"

But React does NOT know this value changed.

So React does not re-render the component.

Result:

👉 Button still shows Login

Even though the variable changed.

Why?

Because React only tracks state changes, not normal variables.

Local variables are just temporary values inside the function.

Every time React renders the component again, the function runs again and:

btnName = "Login"

It resets again.

2️⃣ State Variable (useState)

Your code:

const [btnName, setBtnName] = useState("Login");

Here React creates a state variable.

Example:

<button
  onClick={() => {
    setBtnName("Logout");
  }}
>
{btnName}
</button>
What happens now?

Initial render:

btnName = "Login"

UI shows:

Login

When user clicks button:

setBtnName("Logout")

Now React does 2 things:

1️⃣ Updates state value
2️⃣ Re-renders the component

Now UI becomes:

Logout
3️⃣ Visual Flow
Local Variable

   ↓

   ↓

   ↓

   ↓

   ↓

State Variable
Render
   ↓

4️⃣ Why React Needs State

React UI is based on this rule:

UI = Function(State)

Meaning:

If state changes → UI automatically updates

That is why React uses useState.

5️⃣ Real Life Example

Imagine a scoreboard in cricket.

Local variable = writing score on paper in your pocket.

score = 50
score = 60

But stadium screen doesn't update.

State variable = updating the electronic scoreboard

setScore(60)

Immediately the stadium screen updates.

6️⃣ Short Interview Answer (Important)

Difference between local variable and state variable in React:

| Local Variable               | State Variable           |
| ---------------------------- | ------------------------ |
| Normal JS variable           | React managed variable   |
| React does not track changes | React tracks changes     |
| No re-render happens         | Component re-renders     |
| UI will not update           | UI updates automatically |

7️⃣ One More Important Improvement In Your Code

Your button always becomes "Logout".

Better toggle:

<button
  className="loginbutton"
  onClick={() => {
    btnName === "Login" 
      ? setBtnName("Logout")
      : setBtnName("Login");
  }}
>
{btnName}
</button>

Now it switches:

Login → Logout → Login


1️⃣ When State Changes → React Re-renders

In your example:

const [btnName, setBtnName] = useState("Login");

When the button is clicked:

setBtnName("Logout");

React does these steps:

Updates the state value

Re-runs the component function

Creates a new Virtual DOM

Compares it with the previous Virtual DOM

Updates only the changed element in the real DOM

2️⃣ Virtual DOM Concept

React does not directly update the real browser DOM immediately.

Instead it creates something called:

Virtual DOM

This is a JavaScript object representation of the UI.

Example:

Before clicking button:

<button>Login</button>

After clicking button:

<button>Logout</button>

React now has:

Old Virtual DOM

New Virtual DOM

3️⃣ Diffing Process

React compares:

Old Virtual DOM
vs
New Virtual DOM

This process is called Diffing.

React checks:

What changed?

What stayed the same?

In your case:

Header
 ├ Logo
 ├ Heading
 ├ Hindupur Logo
 ├ Nav Items
      └ Button (Login → Logout)

Only button text changed.

4️⃣ React Updates Only That Part

React will update only the button text in the real DOM.

It will not re-create the entire Header component in the browser DOM.

So instead of doing this ❌:

Delete entire Header
Create Header again

React does this ✅:

Update only the button text
5️⃣ Why React Is Fast

Because of this process:

State Change
      ↓
Component Re-render
      ↓
Virtual DOM Created
      ↓
Diffing Algorithm
      ↓
Update Only Changed DOM Element

So in your example:

👉 React diffs the Virtual DOM
👉 Finds that only the button text changed
👉 Updates only that button in the real DOM

6️⃣ Perfect Interview Answer

You can say like this:

When a state variable changes in React, the component re-renders and React creates a new Virtual DOM. React then performs a diffing algorithm to compare the previous Virtual DOM with the new one. After finding the difference, React updates only the changed elements in the real DOM instead of re-rendering the entire DOM. For example, if a button text changes from "Login" to "Logout", React updates only that button element.
