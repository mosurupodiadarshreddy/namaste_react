Good—this is a small line but very important concept 👍

You wrote:

const { name, location, avatar_url } = this.state.userInfo || {};
🔥 Why we use || {}

👉 Simple answer:

To avoid error when data is not yet available

🧠 What happens WITHOUT it?

Initial state:

this.state = {
    userInfo: {}
};

But imagine if userInfo was:

userInfo = undefined

Then this line:

const { name } = this.state.userInfo;

👉 Will crash ❌

Cannot destructure property 'name' of undefined
✅ What || {} does
this.state.userInfo || {}

👉 Means:

If userInfo exists → use it
If userInfo is undefined/null → use empty object {}
🔁 Example
Case 1: Data not yet loaded
userInfo = undefined

👉 becomes:

undefined || {} → {}

👉 safe destructuring:

const { name } = {};

👉 no error ✅

Case 2: Data loaded
userInfo = { name: "adarsh" }

👉 becomes:

{ name: "adarsh" } || {}

👉 same object used ✅

🧠 Why this is needed in YOUR case

Because:

👉 First render happens BEFORE API call finishes

So temporarily:

userInfo = {}

(or sometimes undefined depending on code)

⚡ Simple understanding

👉 || {} = safety fallback

🔥 One-line memory

👉 “If data not there, use empty object instead of crashing”

💡 Alternative (modern way)

You can also use optional chaining:

this.state.userInfo?.name

But for destructuring:

const { name } = this.state.userInfo || {};

is common.

🧠 Final takeaway
React renders before API completes
Data may be missing initially
|| {} prevents crash
