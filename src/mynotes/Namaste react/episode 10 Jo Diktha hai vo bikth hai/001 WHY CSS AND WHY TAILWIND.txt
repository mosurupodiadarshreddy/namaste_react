Why do we need CSS in React?

React only handles the UI structure and logic.

Example:

<h1>Hello</h1>
<button>Click</button>

Without CSS, it looks plain.

CSS is used for:

Colors
Layout
Spacing
Responsive design
Animations
Professional UI
Different ways to style React applications
1. Normal CSS Stylesheets

Traditional method.

Example:

App.css
.title {
  color: red;
  font-size: 30px;
}
App.jsx
import "./App.css";

function App() {
  return <h1 className="title">Hello</h1>;
}
Pros
Simple
Easy to understand
Traditional
Cons
Global CSS conflicts
Hard to maintain in big projects
Class names can clash
2. Inline CSS
<h1 style={{ color: "red", fontSize: "30px" }}>
  Hello
</h1>
Pros
Quick styling
Cons
Not reusable
Ugly for large UI
No media queries easily

Mostly used for:

Dynamic styles
Small conditional styling
3. CSS Modules

Avoids global conflicts.

Example:

App.module.css
.title {
  color: blue;
}
App.jsx
import styles from "./App.module.css";

<h1 className={styles.title}>Hello</h1>;
Advantage

Scoped CSS.

Used in many enterprise projects.

4. Styled Components

CSS written inside JavaScript.

Example:

import styled from "styled-components";

const Button = styled.button`
  background: black;
  color: white;
`;

function App() {
  return <Button>Click</Button>;
}
Advantages
Component-based styling
Dynamic styling with props
Cons
Extra library
More JS processing
5. Material UI (MUI)

This is what Akshay probably started introducing.

MUI

MUI is a prebuilt React component library.

Instead of creating buttons/cards from scratch:

<Button variant="contained">
  Save
</Button>

MUI already provides:

Buttons
Cards
Tables
Modals
Forms
Responsive layouts
Why companies use MUI?
Fast development
Professional UI
Accessibility support
Consistent design
Cons
Heavy bundle size sometimes
Customization can become difficult
6. Tailwind CSS (Most Popular Modern Approach)

Tailwind CSS

This is utility-first CSS.

Instead of writing separate CSS files:

<button className="bg-blue-500 text-white p-2 rounded">
  Click
</button>

Everything is directly in class names.

Why Tailwind became very popular?
1. Faster Development

No need to:

Create CSS files
Think of class names
Switch between files
2. No CSS Conflicts

Classes are utility-based.

Example:

p-4
text-center
bg-red-500

Very low chance of collision.

3. Easy Responsive Design
<div className="md:flex lg:grid">

Very easy mobile responsiveness.

4. Consistent UI

Spacing/colors come from a design system.

5. Great for React Component Architecture

Each component contains:

HTML
JS
Styling

All together.

Very maintainable in React.

Why many modern companies choose Tailwind over traditional CSS?

Because in large React apps:

Traditional CSS problems:

Huge CSS files
Naming confusion
CSS conflicts
Dead unused CSS

Tailwind solves most of these.

That’s why startups and modern frontend teams prefer it.

But when do companies still use MUI?

Many enterprise companies use:

React + MUI
OR
Tailwind + component libraries

Because MUI gives ready-made enterprise components quickly.

Especially:

Dashboards
Admin panels
Internal tools
Simple interview answer

If interviewer asks:

“Why Tailwind CSS?”

You can say:

Tailwind CSS is a utility-first CSS framework that helps build responsive and consistent UI faster without writing separate CSS files. It avoids global CSS conflicts, improves maintainability in large React applications, and works very well with component-based architecture. That’s why many modern React projects prefer Tailwind over traditional CSS stylesheets.

Real-world understanding
Traditional CSS approach
<div className="card"></div>

Then go to CSS file.

Tailwind approach
<div className="p-4 shadow-lg rounded-xl bg-white"></div>

Everything is directly visible.

That is the biggest philosophy difference.
