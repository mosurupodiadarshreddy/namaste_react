Let’s clearly compare:

BEFORE Tailwind (Traditional CSS)

We used:

JSX
<div className="header">
CSS
.header {
  display: flex;
  justify-content: space-between;
  padding: 20px;
}
How this worked internally
className="header"
        ↓
Browser searches ".header" class in CSS
        ↓
Applies matching styles

So:

You create custom class names
Then define CSS separately
Problem with traditional CSS

In big projects:

Too many CSS files
Naming confusion
Global conflicts
Unused CSS
Switching between JSX and CSS constantly

Example:

header
header2
mainHeader
headerWrapper
headerContainer

Naming becomes messy.

AFTER Tailwind

Now you write:

<div className="flex justify-between p-5">

No separate CSS needed.

What is flex here?

flex is NOT your custom class.

It is a predefined Tailwind utility class.

Tailwind already knows:

.flex {
  display: flex;
}
Internal Working of Tailwind

This is the MOST IMPORTANT understanding.

Step 1: Tailwind scans your React files

From:

content: [
  "./App.js",
  "./src/**/*.{js,jsx}"
]

Tailwind scans all components.

It finds:

className="flex justify-between p-5"
Step 2: Tailwind identifies used utilities

Tailwind detects:

flex
justify-between
p-5
Step 3: Tailwind generates actual CSS

Internally it creates:

.flex {
  display: flex;
}

.justify-between {
  justify-content: space-between;
}

.p-5 {
  padding: 1.25rem;
}
Step 4: PostCSS processes generated CSS

PostCSS

PostCSS helps Tailwind:

process directives
optimize CSS
generate final output
Step 5: Parcel bundles final CSS

Parcel

Parcel bundles:

JS
CSS
assets

and sends optimized files to browser.

Final Browser Flow
React JSX
   ↓
Tailwind utility classes detected
   ↓
Tailwind generates CSS
   ↓
Parcel bundles CSS
   ↓
Browser applies styles
MOST IMPORTANT DIFFERENCE
Traditional CSS

You create:

custom class name
custom CSS

Example:

<div className="header">
.header {
  display: flex;
}
Tailwind CSS

You directly use ready-made utility classes.

Example:

<div className="flex">

No CSS writing needed.

Why called “Utility First”?

Because each class does ONE small job.

Example:

flex              → display:flex
p-4               → padding
text-center       → text align
bg-red-500        → background color
rounded-lg        → border radius

Small reusable utilities.

Real-world analogy

Traditional CSS:

You build furniture from wood manually

Tailwind:

You assemble ready-made LEGO blocks

Much faster.

TAILWIND APPROACH
<div className="bg-white p-5 rounded-lg shadow-lg">

Everything inline.

Why companies like Tailwind

Because:

Faster development
No CSS file switching
Less naming confusion
Consistent spacing/colors
Better maintainability
Smaller CSS bundle
One more VERY important concept

Tailwind DOES NOT include all utilities in final CSS.

It generates ONLY used classes.

Example:

If you only use:

flex p-5 text-red-500

then only those CSS utilities are generated.

This keeps bundle size small.

Interview Explanation

If interviewer asks:

“How does Tailwind work internally?”

You can say:

Tailwind CSS is a utility-first framework that provides predefined utility classes like flex, p-4, and text-center. During build time, Tailwind scans React files for used class names, generates only the required CSS utilities, and PostCSS processes them into optimized browser-compatible CSS. Parcel then bundles the generated CSS and serves it to the browser.
