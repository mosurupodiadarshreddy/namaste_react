1. Server Side Routing
Definition

In server-side routing, when the user navigates to a new page, the browser sends a request to the server, and the server returns a new HTML page.

How it works

Flow:

User clicks link
→ Request goes to server
→ Server returns new HTML page
→ Browser reloads page
Example (Traditional Websites – HTML / JSP / Django / PHP)
<a href="/about">About</a>
<a href="/contact">Contact</a>

Server routes:

app.get("/about", (req, res) => {
  res.render("about.html");
});

app.get("/contact", (req, res) => {
  res.render("contact.html");
});
Characteristics
Server Side Routing
Full page reload
New HTML from server
Slower navigation
SEO friendly
Traditional websites
State resets
Used in:
JSP / Servlets
Django
PHP
ASP.NET MVC
Traditional websites
2. Client Side Routing
Definition

In client-side routing, navigation happens inside the browser using JavaScript without reloading the page. Only components are updated.

This is what React Router does.

How it works

Flow:

User clicks Link
→ React Router intercepts
→ URL changes
→ Matching component renders
→ No page reload
React Router Syntax
import { createBrowserRouter, RouterProvider } from "react-router-dom";

const router = createBrowserRouter([
  {
    path: "/",
    element: <Home />
  },
  {
    path: "/about",
    element: <About />
  }
]);

function App() {
  return <RouterProvider router={router} />;
}

Navigation:

import { Link } from "react-router-dom";

<Link to="/about">About</Link>
Characteristics
Client Side Routing
No page reload
Components change
Fast navigation
State preserved
Used in React/Angular/Vue
SPA (Single Page Application)

3. Difference Table (Very Important)

| Feature      | Server Side Routing | Client Side Routing |
| ------------ | ------------------- | ------------------- |
| Rendering    | Server              | Browser             |
| Page Reload  | Yes                 | No                  |
| Speed        | Slow                | Fast                |
| Navigation   | Anchor tag          | Link                |
| HTML Pages   | Multiple            | Single              |
| State        | Lost                | Preserved           |
| Example      | JSP, Django         | React               |
| Architecture | MPA                 | SPA                 |

MPA = Multi Page Application
SPA = Single Page Application

4. Simple Real Life Analogy

| Routing             | Example                                   |
| ------------------- | ----------------------------------------- |
| Server Side Routing | Going to new building for each department |
| Client Side Routing | Same building, different rooms            |
| SPA                 | One building                              |
| MPA                 | Many buildings                            |

6. Interview Answer (Best Answer)

If interviewer asks:

Explain client side routing vs server side routing

Answer:

Server-side routing means when a user navigates to a new page, a request is sent to the server and the server returns a new HTML page, causing a full page reload. Client-side routing means routing is handled in the browser using JavaScript, where only the required component is updated without reloading the entire page. Client-side routing is used in Single Page Applications like React for faster navigation and better user experience.

7. Final One-Line Difference (Remember This)

Server Side Routing → Server sends new HTML page
Client Side Routing → React changes component without reloading page
